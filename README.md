# Efficient Model Adaptation

[![Tests](https://github.com/meridian-max/efficient-model-adaptation/actions/workflows/tests.yml/badge.svg)](https://github.com/meridian-max/efficient-model-adaptation/actions/workflows/tests.yml)

A reproducible PyTorch experiment comparing a frozen source model, full fine-tuning and a low-rank adapter on synthetic domain-shift classification. It runs on a CPU, exports split hashes and validation histories, and checks that merging the adapter preserves predictions.

## Run it

Requires Python 3.11 or later, PyTorch and NumPy. No model download, API key or GPU is required.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m pip install -e .
python -m model_adaptation --seeds 7 19 31 --steps 160 --output runs/benchmark.json
python -m unittest discover -s tests -v
```

## Executed result

The checked-in [benchmark report](results/benchmark.json) was generated by the command above on CPU with three seeds, a 32-feature input and six target classes. Each seed uses 1,024 target training examples, 256 validation examples and 512 test examples.

| Method | Trainable parameters | Mean test accuracy | Sample standard deviation |
| --- | ---: | ---: | ---: |
| Frozen source model | 0 | 44.27% | 5.39 percentage points |
| Full fine-tuning | 198 | 90.95% | 0.81 percentage points |
| Rank-2 LoRA | 76 | 95.18% | 0.45 percentage points |

The adapter trains **61.6% fewer parameters** than full fine-tuning in this model. Its unmerged total parameter count is 274, including the frozen base, compared with 198 for the base model. This distinction matters: fewer trainable parameters does not mean fewer total stored parameters before merging.

The target shift is constructed to be low rank, which favors an appropriate low-rank adapter. These results describe this small synthetic experiment only. They do not demonstrate an advantage on language models, GPUs, customer traffic or arbitrary datasets. Training times in the JSON report are local wall-clock observations, not a controlled serving benchmark.

## Method

The adapter implements `y = Wx + b + (alpha/rank) BAx`. The base weight and bias are frozen; `A` and `B` are trainable, and `B` starts at zero so the initial adapter matches the base model.

1. Generate a source-domain teacher and a target teacher with a rank-2 weight shift.
2. Pretrain a linear classifier on separate source-domain data.
3. Adapt identical copies using full fine-tuning and LoRA.
4. Select checkpoints by target validation loss every ten steps.
5. Evaluate the selected checkpoints once on a separate target test split.
6. Report accuracy, cross-entropy, multiclass Brier score and fixed-model bootstrap intervals.

Split tensors have SHA-256 manifests, and row hashes are checked for cross-split duplicates. Seeds, PyTorch/Python versions and training histories are recorded. Bootstrap intervals describe test-example resampling for one fitted model; the across-seed standard deviation separately describes variation across these three runs. Neither establishes real-world generalization.

## Use the adapter

```python
import torch
from model_adaptation.lora import LoRALinear, parameter_counts

base = torch.nn.Linear(32, 6)
adapter = LoRALinear(base, rank=2, alpha=2)
print(parameter_counts(adapter))  # total: 274, trainable: 76
merged = adapter.merged()         # independent ordinary Linear layer
```

The 11 unit tests cover initial equivalence, frozen-base gradients and weights, parameter counts, invalid configurations, reproducible data, merge equivalence and an executed report smoke test.

The implementation uses [PyTorch linear layers](https://docs.pytorch.org/docs/stable/generated/torch.nn.Linear.html). Low-rank adaptation is described in the original [LoRA paper](https://arxiv.org/abs/2106.09685); this repository implements a small educational experiment and makes no claim of inventing that method.
